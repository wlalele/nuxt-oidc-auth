## Introduction

PingFederate is an enterprise-grade identity management solution that supports OIDC and SSO. This provider preset offers tested defaults for PingFederate OIDC authentication with minimal configuration.

## Example Configurations

::callout{icon="i-carbon-warning-alt" color="amber"}
Never store sensitive values like your client secret in your Nuxt config. Our recommendation is to inject at least client id and client secret via environment variables.
::

### Minimal

```typescript [nuxt.config.ts]
ping: {
  baseUrl: 'https://sso.pingfederate.com',
  clientId: '',
  clientSecret: '',
  redirectUri: 'http://localhost:3000/auth/ping/callback',
},
```

### Runtime configuration (build once, deploy everywhere)

All provider configuration properties support runtime environment variable injection. This allows you to build your Docker image once and deploy it to multiple environments (dev, staging, prod) with different settings.

```ini [.env]
NUXT_OIDC_PROVIDERS_PING_BASE_URL=https://sso.pingfederate.com
NUXT_OIDC_PROVIDERS_PING_CLIENT_ID=CLIENT_ID
NUXT_OIDC_PROVIDERS_PING_CLIENT_SECRET=CLIENT_SECRET
NUXT_OIDC_PROVIDERS_PING_REDIRECT_URI=http://localhost:3000/auth/ping/callback
```

The following properties support runtime resolution from environment variables:

| Variable | Description |
|---|---|
| `NUXT_OIDC_PROVIDERS_PING_BASE_URL` | PingFederate server base URL |
| `NUXT_OIDC_PROVIDERS_PING_CLIENT_ID` | OIDC client ID |
| `NUXT_OIDC_PROVIDERS_PING_CLIENT_SECRET` | OIDC client secret |
| `NUXT_OIDC_PROVIDERS_PING_REDIRECT_URI` | Callback URL after authentication |
| `NUXT_OIDC_PROVIDERS_PING_AUTHORIZATION_URL` | Authorization endpoint (absolute URL override) |
| `NUXT_OIDC_PROVIDERS_PING_TOKEN_URL` | Token endpoint (absolute URL override) |
| `NUXT_OIDC_PROVIDERS_PING_LOGOUT_URL` | Logout endpoint (absolute URL override) |
| `NUXT_OIDC_PROVIDERS_PING_USER_INFO_URL` | UserInfo endpoint (absolute URL override) |

The `baseUrl` is used to dynamically generate the `authorizationUrl`, `tokenUrl`, `logoutUrl` and `userInfoUrl` at runtime. If you need to override any specific endpoint URL, set its corresponding variable with an absolute URL.

## Kubernetes / Vault example

When deploying to Kubernetes, inject the environment variables via Vault or a Kubernetes Secret:

```yaml [deployment.yaml]
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nuxt-app
spec:
  template:
    spec:
      containers:
        - name: app
          image: my-registry/nuxt-app:latest
          env:
            - name: NUXT_OIDC_PROVIDERS_PING_BASE_URL
              valueFrom:
                secretKeyRef:
                  name: oidc-config
                  key: ping-base-url
            - name: NUXT_OIDC_PROVIDERS_PING_CLIENT_ID
              valueFrom:
                secretKeyRef:
                  name: oidc-config
                  key: ping-client-id
            - name: NUXT_OIDC_PROVIDERS_PING_CLIENT_SECRET
              valueFrom:
                secretKeyRef:
                  name: oidc-config
                  key: ping-client-secret
            - name: NUXT_OIDC_PROVIDERS_PING_REDIRECT_URI
              value: https://app.production.example.com/auth/ping/callback
```

With the `build once / deploy everywhere` approach, the Docker image is built without these variables set, and they are injected per environment at runtime.

## PingFederate configuration

To configure PingFederate as an OIDC provider:

1. Create an **OIDC Policy** in the PingFederate admin console
2. Register your application with:
   - **Client ID**: The client ID your application uses
   - **Client Secret**: Generated by PingFederate
   - **Redirect URIs**: The callback URL of your application (e.g. `https://app.example.com/auth/ping/callback`)
   - **Grant Type**: `Authorization Code`
   - **PKCE**: Enable if your application uses PKCE (recommended)

The preset uses the following default endpoint paths:

| Endpoint | Path |
|---|---|
| Authorization | `/as/authorization.oauth2` |
| Token | `/as/token.oauth2` |
| UserInfo | `/idp/userinfo.openid` |
| Logout (SLO) | `/idp/startSLO.ping` |
| OIDC Discovery | `/.well-known/openid-configuration` |

OIDC Discovery is supported — the provider fetches the discovery document at runtime for token validation.

## Provider specific parameters

| Option | Type | Default | Description |
|---|---|---|---|
| prompt | `string` | - | Optional. Space-delimited, case-sensitive list of ASCII string values that specifies whether the Authorization Server prompts the End-User for reauthentication and consent. |

For more information, check the [PingFederate documentation](https://docs.pingidentity.com/pingfederate/).
